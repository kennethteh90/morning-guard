3. Where to find each value

Android — PLAY_CLOUD_PROJECT_NUMBER

Not secret. Embedded in the app for Play Integrity.

  1. Play Console → your app → Setup → App integrity (or Google Cloud Console linked to Play).
  2. Find Cloud project number (numeric, often 10–12 digits).
  3. Put in local.properties and GitHub secret PLAY_CLOUD_PROJECT_NUMBER.

Worker — PLAY_APP_SIGNING_CERT_SHA256

Play app signing certificate (not upload key).

  1. Play Console → Setup → App signing → App signing key certificate → copy SHA-256 fingerprint.
  2. Or run repo script after you have the cert: ./scripts/print-android-signing-sha256.sh (upload key — use Play’s app signing value for production).
  3. Worker secret: comma-separated allowlist. Each entry may be colon-separated hex (as Play Console shows), plain hex, or base64 / base64url (padded or not). Play Integrity returns certificateSha256Digest as URL-safe base64 (unpadded); the worker normalizes both sides to the same 32-byte digest before comparing.
  4. Required in production: if this secret is empty or missing, licensed Play Integrity auth fails closed (no certificate is accepted). PLAY_ALLOW_UNRECOGNIZED_DEBUG_CERT=true still requires a matching configured cert.

Worker — PLAY_INTEGRITY_SERVICE_ACCOUNT_JSON

  1. Google Cloud Console → same project as Play Integrity → IAM → Service accounts → Create.
  2. Grant access to Play Integrity API (Google Play Android Developer API / Play Integrity as per current Google docs).
  3. Create JSON key → set as Wrangler secret by piping the file (never commit): npx wrangler secret put PLAY_INTEGRITY_SERVICE_ACCOUNT_JSON --name morning-guard-bible-cache < key.json

Worker — APPLE_TEAM_ID

  1. Apple Developer → Membership → Team ID (10 characters).

Worker — BIBLE_PROXY_SESSION_HMAC_SECRET

HMAC secret for short-lived licensed session tokens (~1 hour). After one successful Play Integrity / App Attest exchange (POST /v1/session), the app sends X-Morning-Guard-Session on chapter requests instead of attesting every time. Generate a long random value (32+ bytes); never commit it. 

npx wrangler secret put BIBLE_PROXY_SESSION_HMAC_SECRET --name morning-guard-bible-cache

Deploy the worker with this secret before shipping an app build that expects /v1/session. If the secret is missing, session minting returns 503 and licensed chapter auth can still use fresh attestation or the legacy token.

Worker — existing secrets

  • API_BIBLE_KEY — API.Bible dashboard
  • API_BIBLE_LICENSED_ENABLED — true
  • BIBLE_PROXY_TOKEN — you choose; keep during rollout for old Android builds only

5. Manual QA checklist

  • Locked gate: Google Messages/SMS visible in shade; WhatsApp held
  • Digest notification: count + app name only (lock screen secret)
  • Magic link: URL has code=; opening fragment-only token does not sign in
  • Internal-track Android: NIV loads via proxy (Play Integrity)
  • Sideload debug full build: WEB/KJV via proxy; NIV fails unless legacy token worker path + old app
  • iOS peace session: shields stay after Device Activity interval ends (app killed)
  • Emergency passphrase: 5 failures → 15 min lock; hash not in app-group JSON
  • Settings: privacy policy opens; no “Clear shields” while locked
  • Sync: note without encryption → empty bible_highlights.note in Supabase

6. Legacy token cutover (later)

# Then remove BIBLE_PROXY_TOKEN from worker
